- **27 pytest tests passed** on Python 3.12. The JUnit report is `unit-tests.xml`.
- All seven relational business models were created, populated and queried on real SQLite with foreign keys enabled. Each model also rejected an orphan fact. **This validates fixture relationships and portable business logic, not the native server dialect.**
- The SQLite versioned runner applied V001/V002, seeded 120 loans and related records, verified every seeded value and the three analytics outputs, and safely skipped repeat migrations.
- Separately executed the actual standalone SQLite V001 SQL, V002 SQL and seed SQL with foreign keys enabled: 120 loans, 24 overdue flags.
- Tested dirty-step rejection, checksum mismatch rejection, existing migration lock rejection, repeat seeding and changed-scale rejection.
- Retail payments and insurance reserve balances were reconciled with independent Python calculations.
- MongoDB and Elasticsearch fixtures/contracts were checked locally. No remote commands were run against these engines.
- Excel CSV fixture relationships and award balances were checked locally. **No workbook was created and no native Excel/PowerShell COM migration was executed here.**
- Parquet V1 and V2 were written with DuckDB, checksummed and verified against 1,200 synthetic readings. Tests verified renaming, NULL preservation, quality classification, join cardinality and calibrated values. Tampering with a file was detected.
- Querywise v5 discovered and queried the new SQLite and Parquet outputs: 120 loans; sensor quality counts 63 missing, 239 outlier, 898 valid. See `querywise-integration.json`.
- `verify_all --require-all` correctly exited 1 because unavailable native runtimes were skipped. Missing sources were not counted as success.

## Repeat locally

Run `python -m pytest -q` for offline tests. Provision each server, run its source README commands, then execute `python -m tools.verify_all --require-all`. Do not infer native PASS from the offline test count. Excel verification requires the workbook outputs created by its native script.

Expected analytics files are labelled `scale1`; they are exact fixture outputs from SQLite reference execution. Native test scripts compare numeric results with small tolerances for engine aggregation differences. Percentiles in the Elasticsearch example are approximate and are not asserted as exact values.

The output database/files used for these checks are intentionally excluded from the ZIP so your first migration run starts clean. Source fixtures, expected results, scripts and reports are included.

## Addendum 2 — all engines in Docker (2026-10-14)

`scripts/run_live_tests.ps1` (`compose.test.yaml`) ran every engine together. `verify_all` gave PASS for SQLite, PostgreSQL 16, MySQL 8.4, MariaDB 11.4, SQL Server 2022, Oracle Free 23, Db2 11.5.9, MongoDB 8.0, Elasticsearch 9.1 and Parquet; Excel was SKIP (needs Windows desktop Excel). The Querywise app also passed end to end on each engine with reader accounts. Pack fixes this required:

- **Oracle:** V001 created an index on `turnarounds.flight_id`, which its UNIQUE constraint already indexes, and Oracle rejects that (ORA-01408). `tools/build_pack.py` now skips such indexes for Oracle, and `oracle/migrations.json` and `V001__schema.sql` were updated. This changes the Oracle V001 checksum.
- **Db2:** database names are limited to 8 characters, so the documented `QWCOMPLEX` cannot be created. The examples now use `QWCMPLX`.
- **Elasticsearch:** `reader_privileges.json` adds the cluster privilege `cluster:monitor/main`, which is part of Elasticsearch's minimal SQL role.
